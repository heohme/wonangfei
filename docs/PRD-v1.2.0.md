# 窝囊费 1.2.0 产品需求方案

状态：四项核心能力待开发；独立 H5 小窗已通过预览确认并获发布授权  
基线：当前项目 1.1.0  
确认日期：2026-11-05

本轮围绕四项能力：更准确的愿望达成预估、商品换算工时、每日愿望小票、历史记录保留。用户已通过可视化评审确认第 2 节的五项选择：先验证 H5 悬浮小窗，再推进四项核心能力；核心能力内部先稳定收入与基金口径，再完善愿望体验。后续用户单独授权开发电脑 H5 小窗，已提供本地预览；用户随后确认预览通过并授权推送远端、部署 H5；四项核心能力不在本次开发范围内。

## 1 产品目标和范围

让用户知道喜欢的东西还差多少、预计多久能点亮，并能回看自己的进度。保持现有奶油绿、数字为主、第一次设置后打开就能看的体验。

| 本轮范围 | 在现版基础上增加什么 |
| --- | --- |
| 历史记录保留 | 保存每日收入与设置生效记录；以后改工资、作息或模式，不改写已结束日期的收入 |
| 愿望达成预估 | 将已有粗略天数完善为按实际计薪日期推算的预计达成日 |
| 商品换算工时 | 在目标详情解释商品全价对应的估算工作时长 |
| 每日愿望小票 | 升级已有分享图，展示目标插画、当前进度，以及有可靠基线时的今日推进 |

固定成本摊销、通勤午餐记账、摸鱼计时、桌面组件、跨夜班、自动法定节假日调休、账号和云同步、本地备份导入导出，放入后续候选范围。本轮不增加商品数量或更换参考价格来源。

H5 与小红书小工具使用一致的业务口径；存储和分享按各端能力适配。两端数据仍分别保存在各自设备或容器内，不自动同步。

优先验证项为 [H5 电脑悬浮小窗](feedback/desktop-floating-window.md)。它先于四项核心能力进行独立验证，不包含原生桌面安装包；本地预览已通过确认，已获得 H5 发布授权，手机和小红书版保持现状。

## 2 已确认的产品决定

| 编号 | 决定 | 已确认方案 | 说明与边界 |
| --- | --- | --- | --- |
| D1 | 两种模式的每日和整月口径 | 每天目标一致，沿用现规则：每日目标为月薪÷当月自然日；仅工作在休息日为 0 | 同一工作日满额相同，但整月并非一定相同。月薪 3,000、11 月 30 天和 21 个工作日，全月全天为 3,000，仅工作为 2,100。本轮不改为整月金额一致 |
| D2 | 历史保护与设置生效时点 | 按日保留；改工资、常用作息时提供「明天起」「更正今天」，默认明天起。更正今天允许重算今天，过去日期锁定 | 本轮不做今日收入的逐秒薪资分段。今日两种模式切换仍可重算今日估算；历史日与累计基金不被重置 |
| D3 | 商品工时按什么计算 | 商品全价÷当前工作模式的标准计薪时薪；不扣已有基金，不套愿望比例 | 表示价格等值工资工时，不等于从现在攒够还需的工时。全天自然小时不能标成工作小时 |
| D4 | 脱敏模式展示哪些新增信息 | 脱敏页只看进度，隐藏预计达成日，不新增差额或工时；原有商品参考价入口保留。剩余金额、工时和预计日期放金额模式的详情中 | 脱敏分享仅展示目标名称、插画、百分比、当天日期与鼓励语；不放月薪、收入、基金、差额、商品价格、工时或预计达成日。当天日期与预计达成日明确区分 |
| P1 | 验证优先级 | 先验证 H5 悬浮小窗，再推进四项核心能力 | 验证范围是支持能力的电脑浏览器；来源网页需保留。原生桌面版不在这次验证中。小窗已通过预览确认并获得单独发布授权 |

以上选择于 2026-11-05 经用户可视化评审确认，作为后续设计依据。以下细节和验收示例按 D1—D4 执行；未来改变口径需先更新本节及相应验收。数据继续只存本机，不引入账号或自动上传。

## 3 现状和概念

### 3.1 现版已经具备的能力

1.1.0 已有每秒刷新、今日和本月收入、全天和仅工作、30 个小目标和 15 个大目标、自定义愿望、优先攒、已购归档、脱敏插画、提醒和分享小票。

现版的「还差约几天」是简单外推，未逐日处理跨月和休息日。本月收入使用当前设置从月初回算。修改设置通过余额基准保留累计基金，未保存完整历史设置，因此不能还原过去每次改薪后的逐日收入。

### 3.2 统一名词

| 名称 | 定义 |
| --- | --- |
| 收入估算 | 按工资、计薪模式和作息估算的收入，不代表实际发薪 |
| 每日目标 | 按 D1 确认口径为当月月薪÷当月自然日数 |
| 今日基金新增 | 当天计薪实际形成的愿望基金增量。排除初始基金、迁移调整、购买与撤销等变动；日内设置变化时，不直接使用当前今日收入×当前比例替代 |
| 累计基金 | 初始基金和历次收入分配等形成的累计估算基金，尚未扣除已购占用 |
| 可用基金 | max(0, 累计基金－已购目标的占用金额) |
| 目标已分配 | 自定义愿望按排序分配到的可用基金，最高不超过目标价格 |
| 目标剩余待攒 | max(0, 目标价格－目标已分配) |
| 内置参照商品 | 用户选来观察可用基金解锁进度的参照物，当前不占用预算、不参与自定义愿望排队 |

所有金额和进度是估算。愿望达标表示估算基金足够，不代表银行卡已存入对应金额；标记已买到是本地记录，不发起支付。

## 4 历史记录与设置生效

### 4.1 用户流程

- 修改工资或常用作息，保存前用两个快捷选项选择「明天起」「更正今天」，默认「明天起」，不用下拉框。
- 选择明天起：保留今天和以前的收入；下一天开始使用新设置。页面关闭期间跨过生效日，再打开时也应按日期应用。
- 选择更正今天：明确提示「会重新估算今天的收入，以前的记录保留」，再由用户确认保存。累计基金保持保存瞬间的余额，之后按新设置继续形成增量，不凭更正操作补发或扣回基金。
- 当天休息／调休覆盖仍只影响指定日期；任何重算范围都必须在确认文案里说明。
- 愿望分配比例调整从保存时刻向后生效；不改写过去的基金新增。首页全天／仅工作仍即时切换今日展示与后续累计，不回改昨天及更早的收入，也不使当前累计基金跳变。

今日收入可因更正或模式切换重算，今日基金新增记录的是实际形成的增量，两者应使用不同名称。不能把更正后的今日收入乘以新比例，伪装成今天已经新增的基金。

### 4.2 查看记录

金额模式的本月视图提供一个轻量的「查看每日记录」入口，打开按月排列的日期与估算收入列表。可切换上一月／下一月，最早到本地记录起点；不新增首页图表或独立底部导航。

- 本月收入＝当月已保留日期收入之和＋今天当前收入估算。今天更正后仅今天变化。
- 仅工资或作息已经安排明日生效时，提示已保存新的生效日期，并允许取消或替换该安排；不能存在同一时点冲突的多条安排。
- 待生效安排仅覆盖用户计划修改的字段；之后切换金额／脱敏或全天／仅工作，不意外取消已保存的明日工资／作息安排。
- 页面关闭期间的日期按当时生效的设置补算，并标为按设置估算，无需打卡或后台常驻。
- 已结束日期不会因后来改工资、作息或模式自动变化。本轮不提供过去日期的手动改账。
- 脱敏模式不直接露出每日工资列表，用户明确切回金额模式后查看。

### 4.3 老数据迁移

- 升级前后的累计基金、已购占用、目标顺序、用户愿望和展示偏好保持一致，不重置为 0。
- 无法恢复旧版本未保存的历史工资和作息。旧当月收入按升级时的旧设置回算，标记「迁移前按设置估算」，不能声称是逐日真实保存的记录。
- 迁移前估算与新版本开始保存的日期需要区分；本月汇总不重复计入迁移当日。
- 首次设置的新用户仍可按首次设置回算本月，标记为初始化估算；基金从用户设置的累计起点计算，不能因初始化月收入重复增加基金。
- 迁移首日没有可靠的日初目标基线时，小票只展示当前进度，不展示今日推进。
- 迁移失败时保留旧数据并允许继续读取，不能以空默认值覆盖旧记录。

## 5 愿望达成预估

### 5.1 展示位置

脱敏首页保留当前插画、百分比和参考价结构。金额模式的目标详情展示：

> 还差 ¥300  
> 按当前设置，预计 11 月 9 日点亮  
> 先攒前面的目标，已计入这次预估

日期仅为示意。预计日期是推算结果，不是承诺；主界面不新增自动弹窗。粗略天数和预计日期不能同时给出互相矛盾的结果。

### 5.2 预测规则

- 从当前时刻和当前可用基金出发，用今天剩余可计薪时间和未来日期推算，不把今天的全部目标再加一遍。
- 使用已生效和已安排的未来工资、作息与基金比例；没有安排的未来沿用当前设置。
- 每日目标逐月计算，处理 28、29、30、31 天和跨年；仅工作模式跳过休息日，并采用已有手动工作／休息覆盖；不猜测法定节假日调休。
- 自定义愿望先计入排在它前面的未购目标待攒额，再计算本目标的预计日期；内置参照商品使用全部可用基金，不额外假定清单占用。
- 标记已买到、撤销购买、修改价格、调整顺序或换参照后，立即重算预测，不影响实际收入记录。
- 已达标显示「已攒够」；比例为 0 且余额不足显示「设置愿望比例后可估算」，不显示虚假日期。
- 若未来没有任何可计薪日期或收入为 0，说明当前无法估算；超出 3 年预测范围时显示「目标较远，暂不估算日期」，不无限遍历。
- 明确区分工资来源的预计增量与真实可支配储蓄；本轮不自动扣除房租等成本。

## 6 商品换算工时

只放在金额模式的目标详情或商品详情，不另做首页计算器：

> 价格约相当于 8 小时工资  
> 按当前工作时薪估算

按 D3 确认口径，标准工作时薪＝当日目标÷当前常用作息的有效计薪小时。即使首页选择全天，也使用工作小时口径，不能拿全天 24 小时的累计速率称为工作时薪。午休计不计薪遵循设置。

- 换算对象为商品全价；已经攒了多少不改变这项换算。
- 不套愿望基金比例。它和达成日期回答的是不同问题，分别标明「价格等值工时」与「剩余攒够时间」。
- 不把它称为真实时薪或扣除成本后的有效时薪。本轮不统计通勤、摸鱼或加班倍数。
- 不受今天恰好休息的影响，使用有效的常用作息；薪资、时长或价格无效时不给结果。
- 不足 1 分钟显示「不足 1 分钟」；其他结果向上取整到分钟，不使用秒级精度；超过 100 小时仅显示约整数小时。
- 脱敏页面和脱敏分享不出现该值，避免增加工资推算线索。

## 7 每日愿望小票

### 7.1 触发与内容

沿用当前分享按钮，先生成预览，再由用户保存或分享。今日视图生成每日小票；本月视图继续保留月收入分享，本轮不增加月度愿望推进统计。

| 金额模式 | 脱敏模式 |
| --- | --- |
| 日期、今日估算收入、今日基金新增、当前目标名称／插画／进度、鼓励语 | 日期、当前目标名称／插画／进度、鼓励语 |
| 可在基线可靠时展示今日推进 | 可在基线可靠时展示今日推进百分比 |
| 不展示设置里的月薪、初始基金或无关个人数据 | 不展示收入、基金、差额、商品价格、工时和预计达成日 |

名称和插画跟随当前选中的目标。没有目标时提示先选一个，或沿用现有收入小票。长目标名称正常换行，不挤压进度和日期。

### 7.2 今日推进的边界

今日推进不能简单等于收盘余额减开盘余额。初始基金、迁移调整、标记已购、撤销购买、修改目标金额和重新排序，均不能被写成今天赚来的进度。

- 仅在有可靠日初基线、目标身份和价格未变、当日未发生影响分配的购买／撤销／排序等事件时，展示该目标因今日收入计入基金形成的进度增量。
- 进度最高 100%，今日推进最低 0，不能把超出目标的基金重复计入该目标。
- 今天新建或换了目标、无法确认旧基线、发生影响分配的操作时，只展示当前解锁进度，省略今日推进，不用猜测值填空。
- 明确标明收入为估算；脱敏小票使用最少必要文字，不把明文工资藏在预览、文件名或分享标题中。

分享图保持奶油绿、一个主要物品和一条进度线，减少表格与说明。分享行为由用户主动触发，不自动发笔记或评论。

## 8 页面布局和双端边界

首页继续保留左上金额／脱敏、右上全天／仅工作，底部简洁图标入口和现有安全区间距。

新增信息集中到目标详情、月收入明细和分享预览。工时、日期、历史列表都不默认堆在首页。设置保存时的日期选择采用快捷点击。

| 能力 | H5 | 小红书小工具 |
| --- | --- | --- |
| 计算与本地历史 | 同一业务规则，浏览器本地存储 | 同一业务规则，使用当前容器允许的本地保存方式 |
| 图片分享 | 浏览器支持时调用分享，否则提供图片下载 | 按平台相册／发布能力和实际权限适配，由用户操作 |
| 页面关闭 | 再打开按时间和有效设置补算 | 再打开按时间和有效设置补算 |
| 后台通知 | 本轮不增加 | 本轮不增加 |

不因历史和预测功能增加登录、云服务或外部请求。工资、作息、愿望与历史数据保存在本机；不自动上传。清理本地数据或更换设备不会自动恢复，首次相关入口需给简短说明。本轮不承诺跨端恢复。

## 9 验收示例

以下采用 D1—D4 已确认口径。金额单位为元；无需用真实工资做测试。

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| A01 | 月薪 3,000，2026 年 11 月，整日设置不变 | 每日目标为 100；全天 24 点满额 100，仅工作在该工作日结束满额 100；仅工作休息日为 0 |
| A02 | 同上，整月一直全天／一直仅工作，21 个工作日 | 两者月累计分别为 3,000／2,100；页面不宣称整月金额相同 |
| A03 | 11 月改工资 3,000→6,000，选择明天起 | 今天与过去日期收入保持；明日起日目标按 6,000÷当月天数；基金在保存瞬间不跳变 |
| A04 | 选择更正今天 | 保存前告知今天收入会重算；昨天及更早不变；累计基金保持操作瞬间余额，后续按新规则新增；今日基金新增排除更正调整 |
| A05 | 月初切换或跨月时页面关闭，再打开 | 已结束日期按其生效设置补算；本月与上月不串账；不依赖页面始终开着 |
| A06 | 28／29／30／31 天月份和跨年 | 日目标使用各日期所属月份自然日数；历史不随当前月份天数改变 |
| A07 | 可用基金 0，日目标 100，愿望比例 100%，仅工作；2026-11-06 周五下班后预测价格 200 的首个目标 | 11 月 7、8 日双休不累计，预计 11 月 10 日工作结束达标；若将 11 月 7 日覆盖为工作，预计提前至 11 月 9 日 |
| A08 | 累计基金 120，已购占用 20，未购目标依次 80、50 | 可用基金 100；分配为 80、20，第二个还差 30；预计日期先满足排在前面的待攒额，不重复分配 |
| A09 | 内置商品参照与排队中的自定义目标同时存在 | 参照使用可用基金；清单按顺序分配；两者预估清楚区分，不额外扣同一笔预算 |
| A10 | 商品全价 100，标准工作时薪 12.5，愿望比例 20%，从零开始攒 | 价格等值工时为 8 小时；从零形成 100 元基金所需的计薪工时为 40 小时，不能把 8 小时当成达成时间 |
| A11 | 今日已有部分收入，或跨月预测 | 仅计算今天剩余时段；跨月按新月天数重算；已有基金不被重复加入 |
| A12 | 愿望比例为 0、无可计薪日、无效时长或超出预测范围 | 不出现无穷值、错误日期或长时间卡顿，使用对应无法估算文案 |
| A13 | 只因标记购买／撤销／排序／改价导致余额或进度变化 | 今日收入和今日基金新增不变；小票不把这类操作写成今日推进 |
| A14 | 新目标或升级首日缺少日初基线 | 小票仅展示当前进度，不显示今日推进 |
| A15 | 脱敏状态生成与保存分享图 | 预览、成图、文件名和分享标题都无工资、收入、基金、差额、价格、工时及预计达成日 |
| A16 | 1.1.0 老数据含初始基金、余额基准、已购与用户目标 | 迁移前后累计基金与可用基金一致，排序与偏好保留，旧估算有标记，失败不覆盖旧数据 |
| A17 | H5 与小红书使用相同演示数据和设备日期 | 计算结果一致；各端分享动作正常，不出现工资自动上传或跨端自动同步 |
